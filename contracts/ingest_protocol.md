# iPhone → Mac ingest protocol v1

Dedicated device channel. It is NOT the ChatGPT MCP tunnel and grants no read/query/model rights.

## Transport
- HTTPS on the Mac's LAN address (default port 47821), self-signed server certificate generated by `phctx ingest-cert`.
- Client pins the server certificate by SHA-256 of its DER bytes (hex, lowercase). No trust-all, no system-CA fallback.
- LAN-only by default; outbox keeps batches until the phone is back on the same network (disclosed latency limitation).

## Pairing (one time, visible)
1. Operator runs `phctx pair-device` on the Mac → prints `host`, `port`, `cert_sha256`, one-time `pairing_code` (8 chars, 10-minute expiry, single use).
2. Phone `POST /v1/pair` JSON `{"pairing_code": "...", "installation_id": "<UUID generated once on phone>", "device_name": "..."}`.
3. Response 200 `{"device_token": "<opaque 43+ chars>", "installation_id": "...", "source_id": "apple_health:<installation_id>"}`. Token stored in iOS Keychain (kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly). Server stores only SHA-256(token).
4. Errors: 400 malformed, 403 `pairing_invalid` (wrong/expired/used code).

## Batches
`POST /v1/batches`, header `Authorization: Bearer <device_token>`, body = `contracts/apple_batch.schema.json` object.
- `installation_id` must equal the token's installation (else 403 `installation_mismatch`).
- Stream ordering: per (installation_id, stream). `sequence` starts at 0; `previous_batch_id` is null for sequence 0, else the batch_id of sequence-1.
- 200 ACK: `{"batch_id","request_hash","committed":true,"upserted":N,"deleted":N,"server_time"}`. Only after this may the phone delete the outbox entry.
- Replay of an already committed batch_id with identical body → the SAME stored ACK (200).
- Same batch_id, different body → 409 `{"error":"batch_conflict"}` (phone must not silently drop; mark for operator attention).
- Wrong predecessor / future sequence → 409 `{"error":"sequence_gap","expected_sequence":N,"expected_previous_batch_id":"..."|null}`. Phone resends from the expected sequence.
- 401 `token_invalid` (revoked/unknown) → stop uploading, keep outbox, show "re-pair needed" in the setup screen.
- 413 body > 8 MiB; 422 schema violation (`{"error":"invalid_batch","detail":"..."}`); 503 `storage_unavailable` (disk full / DB busy) → retry with backoff, keep outbox.
- `deleted_ids` are HealthKit UUIDs of deleted objects (HKDeletedObject.uuid). Unknown UUID → tombstone, never a negative value.

`GET /v1/status` with bearer token → `{"server_time","streams":{"<stream>":{"last_sequence":N,"last_batch_id":"..."}}}` for resync after reinstall/anchor loss.

## Stream naming
`stream` = HealthKit type identifier, e.g. `HKQuantityTypeIdentifierHeartRate`, `HKCategoryTypeIdentifierSleepAnalysis`, `HKWorkoutTypeIdentifier`.
Sample `metric` = same identifier. `unit` = HKUnit unitString used when reading (e.g. `count/min`, `ms`, `kg`, `%`, `kcal`, `min`); category samples use `value_num` = raw enum int and `value_text` = symbolic name; workouts use `value_num` = duration seconds, `unit`=`s`, `metadata.activity_type`, `metadata.total_energy_kcal`, `metadata.total_distance_m` when present.
`native_id` = HKObject.uuid.uuidString. `device` = {name, model, manufacturer, hardwareVersion, softwareVersion} when present. `timezone` = HKMetadataKeyTimeZone if present else the phone's current IANA zone.
