2. CORE CORRECTNESS

Evidence authority: the direct path is repaired, but identifiers are being promoted into evidence

Revising R3-01/R3-02: the conservative observation-generation check is implemented, and the dependency is now persisted. A directly observation-dependent analysis is invalidated by any later observation batch, including disjoint insertions and deletion of non-cited members. Unknown receipts, omitted receipts for analyses, and an unrelated SELECT 1 receipt used with an explicit observation ID are rejected by the tested paths. These are meaningful repairs, with tests that would fail if the corresponding checks were removed.

The unresolved distinction is “this response mentioned an observation ID” versus “this read returned that observation’s evidence.” evidence_ids_in recursively scans all string values. It does not distinguish top-level returned records from IDs inside a record’s payload, evidence list, history, or other descriptive fields. _bind then treats membership in that scanned set as proof that the observation was returned.

A concrete accepted sequence is:

A stored note contains payload.sample_ids = [obs_X].

context_read returns the note, including that pointer, but no observation values.

Its receipt includes obs_X because the recursive scanner finds it.

A new analysis cites obs_X and that receipt.

_bind accepts it, _evidence_versions stamps the observation’s current version, and the saved analysis reads bound=true, current=true.

I reproduced that outcome with the pinned scanner and binding predicates against a reduced synthetic SQLite fixture. This is not a claim about an affected production analysis. It is a counterexample to the claimed guarantee.

The same class of problem exists for a SQL result that merely returns a literal ID. Conversely, the scanner can miss legitimate evidence: object IDs held only as dictionary keys under versions are not scanned. The file return path can deliver actual image bytes while failing to put the corresponding obj: reference into the scanned value set; page_image avoids that particular problem through cite_as. The solution is typed provenance from each handler, not a more elaborate recursive regular expression.

Transitive dependencies are not inherited—and this breaks an ordinary, legitimate workflow

The more important counterexample does not require an unusual client request.

Analysis A is correctly created from an observation query and has an observation dependency. Analysis B then legitimately reads A and cites A’s record ID. The receipt for reading A does not inherit A’s observation dependency. _bind sees a cited record, not an observation, and the receipt’s observation flag is false. B therefore receives record_dependencies.observations=0. Later, an observation batch changes A’s population: A becomes stale, but B remains current because A’s record still exists and _ref_version returns "active" for it.

An already-stale parent can likewise be read and cited in a newly “current” child. The parent’s returned stale annotation does not prevent _bind from accepting it. That is precisely the kind of false certainty durable analytical memory should prevent.

There is a related direct-reader omission: bootstrap returns observation catalog/source information, but does not set the top-level reads_observations flag consumed by Tools.call. An analysis using those counts without explicit observation IDs can therefore lose its observation dependency. The catalog is now snapshot-consistent; its receipt classification is not complete.

Required correction: handlers should issue receipts containing explicitly delivered evidence and inherited dependencies. Reading an analysis should carry its dependency closure and freshness state. An unverified or stale derived record must not become verified-current merely by being read again. This does not require recursively treating every incidental ID in arbitrary user prose as a dependency; follow the explicit evidence_refs/record_dependencies relationships, and distinguish record content from references requiring resolution.

Empty-evidence analyses remain a loophole; receipt reuse itself is not the problem

_require_receipts correctly rejects an analysis with no receipts. But an analysis with evidence_ids=[] and a valid receipt from SELECT 1 passes. _bind has no unread evidence to reject, stores a dependency with observations=0, and the analysis receives bound=true, current=true. The new test checks the missing-receipt case, not this valid-but-irrelevant-receipt case.

Do not fix this by requiring observation IDs for every aggregate. A query returning AVG(...) can be valid evidence without enumerating its entire population. Instead, let receipts distinguish substantive query results, returned record contents, original/page contents, and mere metadata/reference discovery. A table-free constant cannot certify an observation-derived result. An analysis based only on new conversational information may be stored as explicitly unverified rather than acquiring a false database-evidence certification.

Receipt reuse across analyses is not inherently a defect. The same unchanged evidence can support several analyses. Receipts need not be single-use or tied to a topic string. What matters is that the receipt represents the evidence actually delivered, that dependencies remain current, and that the resulting label does not imply semantic entailment.

Import isolation: the named Round 3 failures are cleared

Revising R3-03/R3-04/R3-07: query_readonly now begins a read transaction before checking the marker. Its marker check and requested query share the same WAL snapshot. The regression injects a writer between the check and the data query and requires the old complete result; removing the transaction would expose the newer state and fail the test. This matches SQLite’s documented snapshot behavior.   SQLite

Bootstrap and _source_status now share a transaction. While import is active, catalog output is empty and observation counts, latest-sample time, and coverage are withheld. sources is included in the gated table set. I did not find another direct measurement-query bypass in the reviewed foreground handlers. Records and originals appropriately remain readable; incorrect freshness propagation through saved analyses is the evidence-authority defect above, not a reason to shut down all record retrieval.

The flock is held across the entire non-dry-run import, and the recovery marker contains archive hash, parser version, normalized since, and timezone. A live competing import is refused; an interrupted run cannot be replaced by a narrower or differently zoned run. The tests cover both the held lock and mismatched recovery signatures.

A crash after final retirement but before marker deletion remains fail-closed. Completion and owner-qualified marker deletion occur in one transaction. The lock is an advisory application boundary: all supported import callers must continue using import_export, and operators must not replace/unlink the lock file or directly mutate the archive during an import. I do not treat arbitrary out-of-band database edits as a remaining defect in this foreground implementation.

Repeat correctness: the narrower v9 repair is justified

Revising R3-05/R3-06: non-null old and new groups are re-resolved on upsert; deletion re-resolves the departing group; timezone and non-bookkeeping metadata participate in the shared signature. The representative-movement and metadata-difference regressions directly exercise the prior failures.

The v9 “only previously marked groups” optimization is sound under the normal store invariant that normalized columns agree with raw_json. If two rows have equal new signatures, they also have equal values for every field v8 compared: source measurement fields and device. The new predicate adds distinctions; it does not remove any v8 distinction. With the same smaller-ID representative ordering, every newly qualifying repeat already had an earlier v8-equivalent row. Its group therefore contained a v8 mark and is selected by v9. A group without any old marks cannot acquire a new qualifying repeat merely because the predicate became narrower.

The reported reduction from 279 to 254 marks is consistent with that proof. It is not my independent verification of those 25 production pairs. The partial index changes the cost of locating affected groups, not the logical selection rule.

There is one residual general-API edge: an already-marked row upserted from a non-null origin_key to null retains its old repeat_of. The old group is repaired, but the moved row is no longer in it, no new group is queued, and the upsert does not reset the marker. The normal export producer supplies non-null keys, so I do not make this an independent blocker for the requested foreground/export scope. Either reject null keys for export observations or clear repeat_of on the affected upsert, and add that regression before claiming the general maintenance invariant universally.

Revising R3-08: the importer now compares with the active profile and represents A→B→A as three revisions. Both implementation and test address the earlier “ever recorded” error.

Revising R3-12/R3-13: the validator now requires the consumer-recorded digest, current input digest, and producer-recorded digest to agree, and pins the producer manifest’s bytes. The tests separately exercise a normal upstream rerun, a consumed-digest mismatch, and a manifest-only change. These are genuinely discriminating rather than one redundant test masking another missing check.

The named evaluation summary also requires result and metadata files from both named campaigns. Per-probe live artifacts are checked, and git archive HEAD repairs the prior mismatch between committed package bytes and regenerated working-tree artifacts. Second, artifact hashes establish identity, not whether a human actually performed a live probe; the live recorder remains a trusted operator attestation. 3. VALIDATION SOUNDNESS

The load-bearing claim still unproved

The single remaining load-bearing claim is that a saved analysis’s binding and freshness cover the evidence actually delivered, including dependencies inherited through other records.

The live direct-observation example—with observation-dependent receipts, stored dependency, and successful fresh read—is useful evidence. It does not test reference-only receipts, empty-evidence analyses, or a child analysis whose parent later becomes stale.

NOT_RUN is the right concept, but the implementation can erase observed failures

A provider quota refusal before a turn or tool effects should be NOT_RUN, not a model-safety failure. Likewise, an otherwise clean completed turn whose judge is unavailable is unjudged. Exit 2 is a reasonable representation of incomplete evidence.

The current classifier is not safe enough, because model_call_failed and model_timeout do not prove that no behavior occurred. The foreground wrapper replaces text and trace with empty values whenever run_codex raises ModelError. A timeout or late process failure can occur after tool calls or database writes. Erasing the trace does not establish that no turn or effects existed.

More decisively, summarize.unjudged() ignores the row’s actual hard checks. It removes any row with one of those error codes—or a reason starting judge_failed:—before computing case status and hard failures. Thus a row containing an observed deterministic violation can be converted from FAIL/HARD to NOT_RUN merely because the model or judge also failed. This contradicts the harness comment that other failing hard checks still count.

My isolated classifier checks produced both of these results:

Input evidenceCurrent summarizer result

status=FAIL, hard_failure=true, failed hard automatic check, plus model_call_failedNOT_RUN, hard failure cleared

Failed hard automatic check, plus judge_failed:model_call_failedNOT_RUN, hard failure cleared

That is a real failure-masking path. It does not establish that any of the reported 49 quota-affected runs contained such a violation. Their generic error code alone cannot establish either safety or failure.

Use this precedence instead:

Evidence stateRequired classification

Observed deterministic violation or valid judged failure, even with later infrastructure failureFAIL

Provider refusal before execution, with no observed effectsNOT_RUN

Partial execution or unavailable judge, with no established failureNOT_RUN, preserving partial evidence

Every required execution and judgment completed successfullyPASS

Retain automatic checks and partial traces independently of judge availability. Distinguish provider/quota failure from execution timeout and late CLI failure; do not reconstruct “no turn” from a coarse exception name. The summarizer must never override an observed hard violation with an infrastructure label.

The current release’s model_eval NOT_RUN is nevertheless honest: it refuses to reuse the older passing campaign on the changed write contract. That disposition should remain. The classification defect must be fixed before the next campaign is used for acceptance, but it does not itself require waiting for a particular quota-reset date.

Whether the complete rerun must precede foreground use

No—not as a categorical requirement. Once the deterministic authority defects are repaired, a foreground GO-WITH-GAPS can be justified by current engineering regressions and a small current target-host acceptance set covering the changed protocol. The broader frozen regression can remain NOT_RUN until execution is available.

That target-host set should include a normal direct analysis, a reference-only read that cannot certify unread observations, a legitimate parent→child analysis followed by population change, and recovery from an unbound/stale write rejection. It should not depend on the user manually constructing receipts or coaching the successful branch.

A missing full campaign is an acknowledged coverage gap. A demonstrated false-current backend path is not.

5. IDEAL-vs-ACTUAL DIFFERENCE + SUPERIOR REALIZATIONS

First: replace lexical ID collection with handler-owned provenance. The tool handler knows whether it delivered a record body, an observation/query result, a rendered original, or an index/reference. Preserve that distinction in the receipt. Do not let a string in a payload grant the same authority as the referenced data.

Second: make freshness compositional. Derived records need inherited dependencies, not just immediate record existence. A child of a currently valid analysis may be valid; when the parent’s underlying evidence changes, the child must invalidate. A stale or unverified parent cannot be refreshed by rereading its prose.

Third: preserve the conservative observation-generation rule. It now solves the original disjoint-window problem without needing a general SQL dependency parser. Do not replace it with another selective heuristic. Extend it consistently to bootstrap-derived results and inherited dependencies, then optimize only if measured false invalidations justify the complexity.

Fourth: separate execution availability from observed correctness in evaluation. Record provider failure, partial execution, automatic violations, judge availability, and judged outcome separately. Derive PASS/FAIL/NOT_RUN using explicit precedence. This prevents both quota exhaustion being called unsafe behavior and unsafe behavior being erased because a later call failed.

Fifth: retain the working import and provenance boundaries. There is no reason to rewrite the lock/snapshot design or repeat the previous manifest redesign. Add null-key handling and summary-shape validation as small hardening changes. Keep exact-host enrollment controlled; the current narrative reports eight observed regions, but increasing region count is still not evidence that a wildcard is safe.

These changes do not require another interface, a dashboard, a multi-agent system, or user-managed evidence tokens.

6. GO / NO-GO

NO-GO for the present authoritative-analysis contract at 72f27da. The decisive blocker is narrower than in Round 3: receipts and record dependencies do not yet make evidence authority compositional or distinguish delivered data from mentioned identifiers.

The smallest clearing change has three parts:

Typed receipt provenance: distinguish actual delivered evidence/query results from incidental pointers; prevent constant or reference-only reads from certifying an unrelated population.

Inherited freshness: propagate explicit dependencies through cited derived records, reject or mark unverified stale/unbound parents, and include observation-dependent bootstrap output.

Discriminating tests plus a current live probe: cover pointer-only binding, empty-evidence constant receipts, valid parent→child invalidation, stale-parent reuse, and bootstrap-derived counts. Preserve legitimate reuse of the same substantive receipt across multiple analyses.

Separately, fix the evaluation precedence bug before using another campaign for acceptance. An observed hard violation must survive model or judge failure. Do not infer that the 49 quota-affected runs were all harmless or all unsafe from model_call_failed; retain whatever partial traces, database diffs, and automatic checks exist.

The full Codex rerun is not the mandatory predecessor to foreground GO-WITH-GAPS. After the authority repairs and targeted current-host checks, a scoped foreground release with model_eval=NOT_RUN is defensible. The reported September 29 quota reset is an availability condition, not a software correctness gate. The older passing campaign must remain historical because it predates the changed write contract.

Until then, independent primary capture and original storage remain a defensible narrower use. Saved interpretations may be retained, but the system should not present the demonstrated indirect paths as verified-current.
