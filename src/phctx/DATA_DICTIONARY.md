# Personal Health Context — data dictionary (schema v13)

All times are stored as UTC ISO-8601 (`...+00:00`) with the original IANA timezone alongside.
Windows are half-open `[start, end)`. Values keep their original unit; nothing is silently converted.

## Model-readable tables (context_query)
| table / view | meaning |
|---|---|
| `records` | Every user/analysis record, including superseded revisions. Columns: id (`rec_*`), kind (event/routine/question/analysis/note/attachment/preference), occurred_at, timezone, text (original wording), payload_json (structured fields; `approximate`, `synthetic`, `state` for questions…), source_id, source_key, object_sha (original file), supersedes (older revision id), created_at. |
| `active_records` | `records` minus superseded revisions. Use this for "current" facts. |
| `observations` | Imported measurements, including tombstones. id (`obs_*`), source_id, native_id (HealthKit UUID or export fingerprint), metric (HealthKit identifier), start_at, end_at, timezone, value_num, value_text, unit, raw_json (all original fields), deleted (1 = removed at source), updated_at, source_name, bundle_id, repeat_of (id of the earlier identical source record, else NULL), origin_key (equivalence key, contracts/normalization.md: metric, whole-second UTC start/end, normalized value, unit, source name). native_id is source identity: export rows are `x2:` + a fingerprint of every attribute and child element (pre-v4 archives: `x:`). |
| `active_observations` | observations with deleted=0. |
| `canonical_observations` | active_observations minus (a) XML-backfill rows whose origin_key has a `supersessions` row (the live iPhone stream delivered the same sample, in either order; a live deletion keeps the backfill copy hidden) and (b) export rows marked `repeat_of` (an exact repeat of an earlier source record: every field equal except creation/import bookkeeping — `metadata.creation_date`, `metadata.import`, `metadata.source_version`, `native_id`; 254 rows in the real archive). Use for counting/averaging. Rows that share an origin_key but differ in device, timezone or value stay (the key is an equivalence heuristic, not an identity). Different devices are NOT deduplicated — check source_name/bundle_id before summing (watch vs phone steps overlap). |
| `canonical_observations_raw` | The same without (b): every permitted source record. |
| `supersessions` | origin_key → live observation id that makes the export copy non-canonical. |
| sources | `apple_health_export` (HealthKit identifiers as metric, device name in source_name), `oura` (metric `oura.<collection>`: daily_sleep/daily_readiness/daily_activity scores, sleep periods (value s), heartrate (bpm), daily_stress, daily_spo2, daily_cardiovascular_age, workout, …), `whoop` (metric `whoop.<collection>`: cycle and workout strain, recovery %, sleep performance %). For Oura and WHOOP the whole vendor record is in raw_json.raw (e.g. `json_extract(raw_json,'$.raw.score.hrv_rmssd_milli')`), headline in value_num. |
| `observation_catalog` | Per source/metric/unit: row count, first/last start_at. Maintained at ingest; the fast way to see what exists. |
| `sources` | source id, label, policy (durable/ephemeral/blocked), state, last_attempt_at, last_success_at, latest_sample_at, cursor, coverage_json. latest_sample_at is not proof of complete coverage. |
| `objects` | Immutable originals: sha256, size, detected mime, display filename, created_at. Bytes live in `objects/<sha256>`. |
| `object_pages` | Derived text per page (1-based) of an original: object_sha, page, text, method (`pdf_text`, `utf8`, `model_vision:<model>`), sha256 of the text (the page's evidence version; re-extraction changes it). Derived — the original stays authoritative. |
| `extractions` | Per-original extraction status: pending/done/partial/failed/not_applicable, method, page_count, error_code. |
| `evidence_links` / `evidence_refs` | What an analysis/question cites; evidence_refs stores the version seen (record active, observation updated_at, object immutable) so later revisions/deletions mark it stale. |

Evidence ID forms: `rec_<hex>`, `obs_<hex>`, `obj:<sha256>` or `obj:<sha256>#p<page>`. Every read returns a `read_receipt` naming the evidence whose content it delivered: record bodies (bootstrap, search, read), page text (`obj:<sha>#p<n>`), original bytes or a rendered page (`obj:<sha>`). A `context_query` receipt certifies its result as a whole and delivers no individual id (a cell's origin is unknown to the store); an analysis of it cites no row ids and depends on the observations read. Ids that content only mentions (a payload's pointers, evidence lists, history, `mode=info`) are not delivered. An analysis, or any write citing evidence, must pass the receipts of the reads whose results it uses; it is refused if the evidence is not among them (`evidence_unbound`), changed after the read (`stale_evidence` — for observation data, including bootstrap's catalog and source status, any new observation batch), or is a derived record that is already stale. `evidence.current` means every declared dependency is still valid, inherited ones included: a child analysis turns stale when a cited parent does, and citing an unverified derivation leaves the child unverified. `evidence.bound=false` (freshness unverified) marks records written without receipts, analyses whose reads certified nothing (e.g. `SELECT 1`) and anything citing them. A query receipt that also read records or extracted pages certifies nothing (unverified). Schema v11/v13 unverified every certification made under the earlier rules and voided their receipts. Oura and WHOOP sync upsert only: a document the vendor deleted stays until reconciled. `current` never claims the conclusion follows from the evidence. While an Apple import is unfinished, observation queries (including `sources`) refuse (`import_in_progress`), and bootstrap/source status withhold observation counts.

## Not model-readable
receipts (idempotency results), preferences (via bootstrap), insights (outbox), shadow_insights (shadow-mode candidates: never surfaced, audit only), jobs/leases/worker_runs/model_calls (worker bookkeeping, no health text), devices/pairing_codes/sync_streams (device auth), import_runs, changes (change log), meta/migrations.

## Export format (`phctx export DIR`)
records.jsonl (one decorated record per line), observations.csv, originals/<sha256> + originals_index.json, extracted_pages.jsonl, preferences.json, this file.
